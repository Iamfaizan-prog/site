DataPilot-lite

A one-command pipeline that turns a messy invoice export into a formatted workbook and a PDF summary.

Role
Design and build
Stack
Python, pandas, openpyxl
Interface
CLI and Streamlit
Repository
github.com/faizanlinuxx

The problem

Invoice exports arrive as a single sheet: mixed date formats, repeated rows from a double sync, and totals that only line up after a manual pass. The clean-up took most of an afternoon each month, and the result depended on who did it.

What it does

One command reads the export, repairs what can be repaired, and writes two files: a formatted workbook and a one-page PDF summary built from the same cleaned data.

Readraw .xlsx
Validatetypes, missing ids
Dedupedate + client + amount
Formatsheets, columns, totals
Writexlsx + pdf

Rules it applies

  • Dates are parsed against the three formats seen in the export and written as ISO.
  • A row is a duplicate when date, client and amount match an earlier row.
  • Rows that fail validation are reported in the log and kept for review, not silently dropped.
  • Column widths, number formats and the PDF layout come from one config block.

Inside a run

Every stage writes a line to the log, so a bad month can be traced without opening the script. The numbers below come from a sample export of 1,284 rows.

$ python -m datapilot run invoices_raw.xlsx 10:42:07 read invoices_raw.xlsx 1,284 rows 10:42:07 validate 12 dates repaired 3 rows need review 10:42:07 dedupe 37 duplicates removed 1,247 rows kept 10:42:08 format 2 sheets, 14 columns 10:42:08 write invoices_clean.xlsx 10:42:08 write summary.pdf 10:42:08 done 1.56s exit 0

Sample output

The cleaned sheet keeps the source rows readable. A repaired date is marked, and a duplicate is struck rather than deleted, so the monthly numbers can still be checked against the export.

Sample rows. Client names and amounts are invented for the demo; the shape matches a real export.

What changed

  • The monthly clean-up is one command and a log instead of an afternoon.
  • Dates, duplicates and totals are handled the same way every month, whoever runs it.
  • The PDF summary is generated from the cleaned data, so it cannot drift from the workbook.

Limits and next

  • The PDF layout is fixed to one template. A second template would need a small refactor of the report module.
  • There is no database. The workbook is the source of truth, which suits this size and stops suiting it past a few hundred thousand rows.
  • New export formats need a mapping entry. The pipeline does not guess columns, because a wrong guess is worse than a failed run.

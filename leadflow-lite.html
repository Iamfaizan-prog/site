LeadFlow-lite

A lead intake workflow that validates, dedupes, scores and drafts a first reply, then waits for a human to send it.

Role
Design and build
Stack
n8n, FastAPI, Gemini API
Interface
Webhook and Google Sheets
Repository
github.com/faizanlinuxx

The problem

Leads arrived from a form and from an inbox. Someone copied them into a sheet, checked for repeats, guessed how warm each one was, then wrote a reply. The first response depended on who was at the desk, and the same lead sometimes appeared twice with a different phone number.

What it does

A webhook takes the form post and an inbox rule forwards the rest. Every lead goes through the same path, and the run ends with a sheet row plus a drafted reply, never a sent one.

Intakeform + inbox
Validateemail, phone
Dedupeemail + phone
Classifyhot, warm, cold
Routesheet + draft

Rules it applies

  • A lead is a duplicate when the email matches, or when the normalised phone number matches an existing row.
  • Classification returns hot, warm or cold with a one-line reason, so a person can disagree with it.
  • Replies are written to drafts. The workflow never sends mail on its own.
  • Each step retries twice, then logs the failure and leaves the row for review.

Inside a run

This run took five leads from the form and the inbox. Two were duplicates, three were new, and each new lead left with a score and a draft.

$ leadflow run --source form,inbox 09:15:02 intake form Marta Ruiz 09:15:02 validate email + phone ok 09:15:03 dedupe no match 09:15:04 classify hot dispatch backlog, clear budget 09:15:04 route sheet row 214 + draft reply 09:15:05 dedupe 2 duplicates skipped 09:15:05 done 1.84s exit 0

Sample output

The sheet keeps the score and the reason next to the lead. Duplicates stay in the log rather than the sheet, so the count of new leads stays honest.

LeadSourceScoreNext
Marta Ruizformhotdraft ready
Devon Parkinboxwarmdraft ready
Aster Labsformcoldsheet only

Sample rows. Names, scores and reply text are invented for the demo.

What changed

  • A first reply is drafted in the same run as the intake, so the wait is a review, not a blank page.
  • Duplicates are caught before they reach the sheet, including the same person using a second phone number.
  • Every score carries a reason, so a person can overrule it without re-reading the whole thread.

Limits and next

  • Classification is a suggestion. A human approves every reply, and that is deliberate.
  • There is no CRM sync yet. Google Sheets is the handoff, which keeps the first version cheap to change.
  • The inbox parser handles plain-text and HTML bodies, not attachments. A PDF brief still needs a person.
